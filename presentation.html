📌 Executive Overview

Problem Statement & Project Vision

Transforming conventional campus placement procedures into an automated digital portal.

⚠️
Legacy Challenges

Manual spreadsheets, delayed email notices, lack of real-time application tracking, and high administrative overhead for placement officers.

🎯
The Solution

PlaceMate provides a centralized, role-based platform connecting Students, Companies, and Placement Officers with automated eligibility verification.

🌟
Key Impact

Instant profile evaluation, automated deadline enforcement, real-time KPI dashboards, and automated email confirmation notifications.

📂 Project Structure

Modular Django Apps Hierarchy

Clean separation of concerns organized into distinct domain applications.

`apps/accounts`

Handles user authentication, custom `User` model, role selection, login, registration, and password reset flows.

`apps/student_portal`

Manages student profiles, dashboard views, eligibility calculations, drive details, and application submissions.

`apps/company_portal`

Manages company profiles, drive publishing, candidate resume reviews, and interview scheduling.

`apps/admin_portal`

Provides placement officer tools, officer profile management, and university-wide placement statistics.

`apps/common`

Houses shared models including `PlacementDrive`, `Department`, and `Skill` accessible across portals.

`templates/`

Stores structured HTML templates segregated by app domain (`shared/`, `accounts/`, `student_portal/`).

🗃️ Database Schema

Database Model Relationships

Robust relational schema designed with integrity constraints and foreign keys.

One-to-One Relations

`User` ↔ `StudentProfile` and `User` ↔ `CompanyProfile` ensure direct identity mapping and role separation.

One-to-Many Relations

`CompanyProfile` → `PlacementDrive` and `StudentProfile` → `Application` allow multiple entries per parent entity.

Many-to-Many Relations

`PlacementDrive` ↔ `Department` and `PlacementDrive` ↔ `Skill` define multi-department and multi-skill criteria.

💻 Model Breakdown

Model 1: Custom User Entity

Extending Django's `AbstractUser` for email authentication and multi-role access control.

# apps/accounts/models.py class User(AbstractUser): username = None email = models.EmailField(unique=True) STUDENT = "student" COMPANY = "company" OFFICER = "officer" ROLE_CHOICES = [ (STUDENT, "Student"), (COMPANY, "Company"), (OFFICER, "Placement Officer"), ] role = models.CharField(max_length=25, choices=ROLE_CHOICES) USERNAME_FIELD = 'email' REQUIRED_FIELDS = []
Model Key Features
  • Replaces username authentication with standard unique Email authentication.
  • Stores role attributes to dictate access privileges across Student, Company, and Officer portals.
  • Integrates custom `CustomUserManager` for administrative superuser generation.
💻 Model Breakdown

Model 2: Student Profile Model

Storing comprehensive academic credentials, CGPA, backlogs, and resume links.

# apps/student_portal/models.py class StudentProfile(models.Model): user = models.OneToOneField(User, on_delete=CASCADE) full_name = models.CharField(max_length=255) roll_number = models.CharField(max_length=50) university = models.CharField(max_length=255) department = models.ForeignKey(Department, ...) semester = models.PositiveIntegerField() cgpa = models.DecimalField(max_digits=4, decimal_places=2) passing_year = models.PositiveIntegerField() active_backlogs = models.PositiveIntegerField(default=0) resume = models.FileField(upload_to='resumes/') skills = models.ManyToManyField(Skill, blank=True)
Academic Rules & Constraints
  • Stores exact numeric CGPA for instant eligibility evaluation.
  • Tracks active backlogs to filter out ineligible drive applicants automatically.
  • Supports resume PDF file uploads and profile photo image uploads.
💻 Model Breakdown

Model 3: Company Profile Model

Recruiter identity entity storing organizational data and corporate credentials.

# apps/company_portal/models.py class CompanyProfile(models.Model): user = models.OneToOneField(User, on_delete=CASCADE) company_name = models.CharField(max_length=255) industry = models.CharField(max_length=255) website = models.URLField(blank=True) location = models.CharField(max_length=255) description = models.TextField() is_verified = models.BooleanField(default=False)
Recruiter Integration
  • Links every company account directly to a valid user login credential.
  • Acts as the parent model for all job recruitment drives (`PlacementDrive`).
  • Supports verification flag for Placement Officer approval workflows.
💻 Model Breakdown

Model 4: Placement Drive Model

Core job post entity encapsulating eligibility rules and compensation packages.

# apps/common/models.py class PlacementDrive(models.Model): company = models.ForeignKey(CompanyProfile, ...) title = models.CharField(max_length=255) salary_package = models.DecimalField(...) eligible_departments = models.ManyToManyField(Department) min_cgpa = models.DecimalField(max_digits=4, decimal_places=2) max_backlogs = models.PositiveSmallIntegerField(default=0) eligible_passing_year = models.PositiveIntegerField() application_deadline = models.DateTimeField() status = models.CharField(choices=STATUS_CHOICES)
Eligibility Criteria Definition
  • Defines threshold metrics (`min_cgpa`, `max_backlogs`, `eligible_passing_year`).
  • ManyToMany relationship with `Department` to allow multi-stream eligibility.
  • Status lifecycle: `draft` → `published` → `closed`.
💻 Model Breakdown

Model 5: Application Tracker Model

Connecting students with recruitment drives to track recruitment status phases.

# apps/student_portal/models.py class Application(models.Model): student = models.ForeignKey(StudentProfile, ...) drive = models.ForeignKey(PlacementDrive, ...) applied_at = models.DateTimeField(auto_now_add=True) STATUS_CHOICES = [ ('applied', 'Applied'), ('shortlisted', 'Shortlisted'), ('interview_scheduled', 'Interview Scheduled'), ('selected', 'Selected'), ('rejected', 'Rejected'), ] status = models.CharField(choices=STATUS_CHOICES)
Recruitment Pipeline
  • Prevents duplicate applications via backend database lookups.
  • Tracks stage transitions from initial application to final job offer (`selected`).
  • Provides automatic timestamping (`applied_at`) for audit compliance.
💻 Model Breakdown

Model 6: Department & Skill Masters

Normalizing department names and student technical skill tags.

# apps/common/models.py class Department(models.Model): name = models.CharField(max_length=255, unique=True) code = models.CharField(max_length=10, unique=True) class Skill(models.Model): name = models.CharField(max_length=255, unique=True)
Normalisation Advantages
  • Ensures standardized department entries (e.g. Computer Engineering, IT, Mechanical).
  • Allows dynamic skill tagging for student profiles and job posting requirements.
  • Eliminates data redundancy across the entire placement portal.

⚙️ Views Implementation

Dynamic View 1: Student Dashboard

Calculating dynamic profile completion, eligible drive matches, and application KPIs.

# apps/student_portal/views.py @login_required def dashboard_view(request): profile = request.user.studentprofile # Dynamic Eligibility Computation eligible_drives = PlacementDrive.objects.filter( status='published', application_deadline__gt=timezone.now(), eligible_departments=profile.department, min_cgpa__lte=profile.cgpa or 0.0, max_backlogs__gte=profile.active_backlogs or 0 ).exclude(id__in=applied_drive_ids) return render(request, 'dashboard.html', context)
Dynamic Processing Logic
  • Queries live student data and evaluates academic criteria in real-time.
  • Calculates completeness percentage dynamically (0% to 100%).
  • Aggregates count metrics: total applications, interviews scheduled, offers received.
⚙️ Views Implementation

Dynamic View 2: Eligibility Engine

Evaluates student parameters against placement drive rules in `drives_list_view`.

# Eligibility Evaluation Snippet for drive in all_drives: is_eligible = True reasons = [] if profile.department not in drive.eligible_departments.all(): is_eligible = False reasons.append("Department not eligible") if profile.cgpa < drive.min_cgpa: is_eligible = False reasons.append(f"CGPA below {drive.min_cgpa}") if profile.active_backlogs > drive.max_backlogs: is_eligible = False reasons.append("Active backlogs exceed limit")
Automated Safeguards
  • Provides immediate visual eligibility feedback (Eligible vs Ineligible with reason tags).
  • Enforces server-side validation during form submission (`apply_for_drive_view`).
  • Blocks ineligible or expired application requests automatically.
⚙️ Views Implementation

Dynamic View 3: Application Mailer

Processing 1-click job application requests and triggering instant confirmation emails.

Mailer Integration
  • Dispatches automated confirmation emails via Django SMTP backend.

🔒 System Security

Security & Validation Architecture

Implementing enterprise-grade web application security standards.

CSRF Protection

`{% csrf_token %}` injection on all form POST submissions to prevent cross-site request forgery.

Auth Guards

`@login_required` decorators and role verification checks protecting all private client routes.

Form Validation

Server-side Django Form sanitization preventing invalid numeric inputs or unformatted files.

ORM Security

Parameterized Django ORM queries completely eliminating SQL injection vulnerabilities.
